# 训练短响规格同步快照

正式规格：[GitHub #1](https://github.com/hnuQ/fat-loss-calculator/issues/1)；实现工单：[20](https://github.com/hnuQ/fat-loss-calculator/issues/20)。此文件备份 #1 的新增节，后续决定先同步 #1 及受影响开放工单，再同步此快照；不是另一份 canonical spec。

## Confirmed training ringing scope (2026-10-06)

### 目标与证据边界

- 保留普通通知，新增 Android 用户明确选择的“响铃提醒”。仅用于用户自行设置的每周训练日及一个时/分时间，不增加用餐提醒、组间计时、番茄钟、云消息或自动训练内容；微信仍只有前台到点提示。
- #13 的 0.2.0 小米真机证据是自然到时收到通知、用户未听到声音；当时在应用页面，锁屏未验证，精确延迟和无声根因均未确定。见 https://github.com/hnuQ/fat-loss-calculator/issues/13#issuecomment-6006667110 。不能把音量/渠道正常或模拟器投递解释为有声通过。
- 此节取代旧规格中排除独立短响的约束；2026-10-04/05 原有模拟器范围和历史验收保留。新增真机听觉门槛仅用于本次短响功能，不追溯改写旧票或旧包。

### 用户可观察行为

- 新安装提醒默认关闭；升级保留既有启用、星期、时间，模式默认“普通通知”，不得自动升级为强提醒。选择响铃前说明会短暂打断其他音频、对应闹钟音量和后台服务通知；用户可随时切回普通通知。
- 首版采用固定上限：到时短响最多 10 秒，达到上限自动停止；铃声短于上限可在窗口内重复，禁止无限循环。提供“系统默认闹钟铃声”及系统可访问的本地闹钟铃声选择，不新增文件上传、网络下载或自定义时长。试听最多 3 秒，有明确停止入口；试听不保存设置、不安排任务或消费到时事件，离开训练页结束试听。
- 响铃时训练页与通知均有“停止响铃”；停止只结束本次，保留下周安排。重复点击停止无副作用。铃声标识失效时显示回退到系统默认的提示；无法播放时保留可用通知并显示具体状态，不宣称已响铃。
- 普通通知的声音由用户系统渠道设置控制；响铃使用独立原生播放器，采用明确的闹钟音频用途，并显示对应音量状态。尊重用户选择：静音/振动模式、勿扰、对应音量为零时本版不主动响铃，只保留系统允许的通知和原因提示。获取不到状态时不能声称已确定无阻碍。
- 通知权限或训练通知渠道被禁用时，不在后台偷偷播放；提示用户该模式不可用，并提供用户自行打开系统设置的入口。普通通知渠道被用户设为无声时不得自动换渠道绕过；切换独立响铃必须用户主动确认其声音与普通通知渠道分别控制。响铃模式使用的服务/提醒渠道被禁用时也停止主动响铃。
- 不自动调整系统音量、绕过勿扰、申请勿扰绕过能力、改变安全/节电设置或全屏抢占。用户主动启用响铃不等于授权这些变更。原生音频焦点被拒绝或失去时不播放/立即停止并释放，通知仍独立记录可用状态。

### 定时、播放与取消契约

- 精确定时和有声分开设计。需要承诺指定分钟提醒时使用适当的精确闹钟能力及用户授权，运行时检测和重新检查；不把精确闹钟当无声修复。不假定本产品具备 USE_EXACT_ALARM 的适用资格。
- 精确闹钟拒绝、撤销或平台不支持时提示“可能延迟”；普通通知可按非精确定时继续。若后台无法合法启动短响服务，明确降级为普通通知，保留用户所选模式并显示当前有效能力，不偷偷启动服务或显示“准时响铃”。前台试听不证明后台可用。
- 后台播放器在到时启动、结束即释放，依法处理前台服务类型、权限、可见通知、后台启动限制、音频焦点和进程生命周期。广播接收器只负责校验/交接，不在短生命周期接收器中裸放音；不全天常驻，不在重启广播中直接播放。target 35 / Android 15 的音频焦点须前台应用或前台服务，具体服务方案在实现前用官方限制验证。
- 每次发生键包含设置代次和计划时间；同一次只发一份训练通知、启动一次短响，不叠加播放器，不因重复广播、切前后台、重开或续排再次播放。普通通知自带声音与主动短响不得制造双重铃声；独立模式的通知/渠道设计须明确说明并尊重用户控制。
- 关闭提醒、修改星期/时间/模式/铃声时，先使旧代次失效，取消旧任务、关联活动通知和正在播放/试听，再保存及安排下一次未来事件。竞态下旧接收器不得重新响起。关闭后无待发训练任务；再次启用不补响已过期事件。
- 成功完整备份恢复时取消恢复前任务和播放，恢复配置后仅重排未来事件；恢复失败保持原状态和有效安排，不产生部分覆盖。旧备份缺新字段时保留原启用/星期/时间，默认普通通知及系统默认铃声；权限不随备份迁移，恢复后重新检测。设置进入版本化完整备份，运行中的播放器/服务不序列化。
- 重开、设备重启、时间/时区变化和授权恢复只依据当前设置重排未来事件，不追补过期响铃。设备本地星期/时间语义保持；系统强停期间无法保证送达，重开后显示并恢复可用未来安排，不能保证所有厂商或所有版本必定准时。

### 验收标准（全部待实施验证）

- [ ] 自动化覆盖默认关闭、升级/旧备份默认普通通知、新字段往返、无效铃声回退、关闭/改期/切模式/恢复与旧广播竞态、同次去重及不补响；保持健康档案和所有既有记录不变。
- [ ] Android 虚拟设备自然到时验证权限允许/拒绝/撤销、精确能力与降级、停止按钮、10 秒上限、3 秒试听、音频焦点拒绝/丢失、服务退出及资源释放；通知和播放尝试分开记录。不得以广播注入代替自然到时，不以模拟器声音配置替代用户听觉确认。Android 15 / target 35 覆盖合法后台启动与音频焦点限制。
- [ ] 同一 Xiaomi 23049RAD8C / Android 13 真机，用户主动选择响铃且权限/音量允许，在应用前台、桌面后台、锁屏三种情形分别自然到时；用户实际听见所选短铃声。分别记录通知是否看到、响铃是否听见、计划时间、实际通知/播放开始时间、持续时间及延迟；配置、系统调用成功或通知送达不能替代听觉确认。
- [ ] 真机分别验证通知权限拒绝、渠道禁用、渠道无声、对应音量零、静音/振动和勿扰，表现符合上述边界；所有设置变动由用户明确操作或授权。未获用户授权的路径标明未执行，不能自动勾选。
- [ ] 真机验证通知/训练页停止、自动结束、试听停止；正在响时关闭/改期/切模式/完整恢复均结束旧播放并取消旧任务，之后自然等待旧时间不再触发，恢复/重开不重复本次。
- [ ] 测试前保留本地可读个人基线；结束恢复提醒及已授权系统设置，完整状态逐字段核对、强停重开再核对，无残留测试任务/活动通知。只提交脱敏摘要，不上传个人健康备份、截图或原始日志。不可卸载/清数据制造通过。
- [ ] 共享行为回归、类型检查、Android 构建及微信开发者工具前台提示验证通过；微信不暴露可用的后台响铃承诺。候选包的验收结果注明实际版本/哈希，旧 0.2.0 证据不作为新功能通过依据。

### 一手技术依据（2026-10-06 已复核）

- [Android 音频焦点](https://developer.android.com/media/optimize/audio-focus)：播放前申请，拒绝/丢失有对应处理，结束释放；target 35 有前台状态要求。
- [Android 精确闹钟](https://developer.android.com/develop/background-work/services/alarms)：精确能力单独授权与检测，拒绝/撤销及恢复须处理。
- [后台前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)：用户请求的精确闹钟可涉及合法例外，非精确定时不能据此假定能启动服务。
- [通知渠道](https://developer.android.com/develop/ui/compose/notifications/channels)：创建后应用不能直接改声音行为；不删除/重建或换 ID 绕过用户选择。
- [Goodtime AndroidSoundPlayer](https://github.com/adrcotfas/goodtime/blob/master/shared/src/androidMain/kotlin/com/apps/adrcotfas/goodtime/bl/notifications/AndroidSoundPlayer.kt) 与 [AlarmManagerHandler](https://github.com/adrcotfas/goodtime/blob/master/shared/src/androidMain/kotlin/com/apps/adrcotfas/goodtime/bl/AlarmManagerHandler.kt) 仅作后续设计参考；本轮未重新审计该源码，不直接复制 GPL 代码。
